# P1-05 基于项目范围约束、多域嵌套召回与高亮统一映射的快照故障定位方法

- 状态：DRAFT
- 优先级：P1
- 风险：中
- 主要近似来源：通用架构（主）+ 开源方案（次）

## 1) 专利名称

一种基于项目范围约束、多域嵌套召回与高亮统一映射的快照故障定位方法。

## 2) 背景技术

- 故障关键词可能同时出现在标题、描述、代码调用、SQL 内容和远程调用接口中，若只检索单一字段，召回率偏低。
- SQL 与远程调用通常存放于嵌套对象中，若不统一处理，命中结果难以直接回显到检索页面。
- 关键词检索与按表定位属于两类不同场景：前者强调多域召回，后者强调表级精确约束，现有技术常缺少统一出口。

## 3) 现有缺陷

- 多域字段与嵌套字段缺少统一查询模型。
- 高亮片段分散在不同命中域，前端需要二次拼装。
- 检索结果与快照详情/图谱页面之间缺少统一结果对象。

## 4) 技术方案

- 在项目范围内构建关键词检索和表级检索两类统一入口。
- 对标题、子标题、描述、代码字段执行多域布尔召回。
- 对 `sqls.content` 与 `remotes.invokerInterface` 执行嵌套检索。
- 将标题、描述、SQL、远程调用高亮片段统一映射到结果对象。
- 对不可用快照执行结果过滤，并保留更新时间、目录等定位字段。
- 在表级检索场景下，将检索结果进一步映射为"快照-数据表-动作标签"关系输出。

### 变量及字段说明

- `projectId` 表示项目标识；`searchMode` 表示检索模式；`KEYWORD` 表示关键词检索模式；`TABLE` 表示数据表检索模式；`keyWords` 表示输入关键词；`databaseName`、`tableName` 表示目标数据库名和数据表名。
- `title`、`subTitle`、`describe`、`code` 表示基础检索字段；`sqls.content` 表示 SQL 内容字段；`remotes.invokerInterface` 表示远程调用接口字段。
- `titleFragment` 表示标题高亮片段；`describeFragments[]` 表示描述高亮片段集合；`sqlContentFragments[]` 表示 SQL 高亮片段集合；`remoteContentFragments[]` 表示远程接口高亮片段集合。
- `SnapshotSearchResult` 表示统一的快照检索结果对象；`id` 表示结果对象标识；`appId` 表示应用标识；`directoryId` 表示目录标识；`updateTime` 表示更新时间。
- `snapshotId` 表示快照标识；`actionLabels[]` 表示数据表动作标签集合；`snapshotCount` 表示命中快照数量。

## 5) 本发明创造的优点、有益的技术效果

- 提升复杂故障场景下的跨域召回能力。
- 将多域高亮统一回填到一个结果对象，缩短页面处理链路。
- 让关键词检索与表级定位共享同一套快照结果模型，提升跨页面复用能力。

## 6) 权利要求草案

### 独立权利要求1（一句话）

一种快照故障定位方法，其特征在于：在项目范围约束下执行基础字段检索与嵌套字段检索，并将多域高亮片段统一映射为快照结果对象，以支撑故障定位和页面联动展示。

### 从属权利要求2-5

- 权利要求2：根据权利要求1所述的方法，其特征在于，基础字段至少包括标题、子标题、描述和代码字段。
- 权利要求3：根据权利要求1所述的方法，其特征在于，嵌套字段至少包括 SQL 内容字段和远程调用接口字段。
- 权利要求4：根据权利要求1所述的方法，其特征在于，统一结果对象至少包括快照标识、应用标识、目录标识、标题高亮和更新时间。
- 权利要求5：根据权利要求1所述的方法，其特征在于，表级检索结果进一步输出快照与数据表之间的关系和动作标签。

### 技术关键点和欲保护点

- 技术关键点：项目范围约束、多域布尔召回、嵌套检索、高亮统一映射、结果过滤、表级关系输出。
- 欲保护点：以"项目约束 -> 多域召回 -> 嵌套命中 -> 高亮统一映射 -> 结果过滤 -> 页面联动输出"的处理链保护快照检索核心机制。

## 7) 发明内容

本方案由以下六个部件组成，各部件顺序衔接，共同完成快照故障定位中的"项目内召回、证据回填和统一输出"。

### 部件一：查询构建部件

**职责**：把关键词检索和表级检索统一标准化为项目范围内的检索请求。

具体而言，该部件固定加入 `projectId` 约束，并根据 `searchMode` 构建 `KEYWORD` 或 `TABLE` 两种检索入口。数据上，例如 `projectId=P001、keyWords=超时` 时进入多域召回路径；`projectId=P001、databaseName=order_db、tableName=t_order` 时进入表级定位路径。

### 部件二：嵌套检索部件

**职责**：在基础字段召回之外，对 SQL 和远程调用等嵌套字段执行命中判断，补全故障线索来源。

具体而言，该部件对 `sqls.content` 和 `remotes.invokerInterface` 执行嵌套检索，使关键词即使不出现在标题或描述中，也能从 SQL 或远程接口中被召回。数据上，一次关键词检索可同时覆盖 `title`、`subTitle`、`describe`、`code`、`sqls.content`、`remotes.invokerInterface` 共 `6` 类命中入口。

### 部件三：高亮抽取部件

**职责**：把标题、描述、SQL、远程调用中的命中片段统一提取为结构化高亮证据。

具体而言，该部件不直接把原始搜索引擎高亮结构下发前端，而是回填为 `titleFragment`、`describeFragments[]`、`sqlContentFragments[]`、`remoteContentFragments[]` 等字段。数据上，例如关键词为"超时"时，某条结果可同时形成 `titleFragment=<em>超时</em>场景` 和 `describeFragments=[支付回调出现<em>超时</em>]`。

### 部件四：结果过滤部件

**职责**：在统一映射前剔除不可用快照，保证输出对象可展示、可跳转、可复用。

具体而言，该部件在项目范围内对命中快照执行可用状态过滤，避免不可用快照进入结果集。数据上，例如某次检索原始命中 `9` 个快照，但其中 `2` 个状态为不可用，则该部件最终只保留 `7` 个有效快照进入后续映射。

### 部件五：结果映射部件

**职责**：把检索命中统一转换为快照结果对象，避免页面二次拼装不同命中域。

具体而言，该部件输出统一的 `SnapshotSearchResult`，其中至少包含 `id`、`projectId`、`appId`、`directoryId`、`titleFragment`、各类高亮片段和 `updateTime`。数据上，例如一条结果可同时携带标题命中、SQL 命中和远程接口命中，前端只需消费一个对象即可渲染证据。

### 部件六：关系输出部件

**职责**：在表级定位场景下，把检索结果继续映射为"快照-数据表-动作标签"关系数据。

具体而言，该部件在 `TABLE` 模式下汇总同表相关的快照集合，并输出 `snapshotId`、`databaseName`、`tableName`、`actionLabels[]` 等字段。数据上，例如 `databaseName=order_db、tableName=t_order` 时，系统可输出 `snapshotCount=6`，动作标签为"查、改"，便于用户直接做表级故障追溯。

## 8) 具体实施例

### 实施例：关键词"超时"的多域快照故障定位

某次故障检索请求的输入数据如下：

| 项目 | 数值 |
|---|---|
| `projectId` | `P001` |
| `searchMode` | `KEYWORD` |
| `keyWords` | `超时` |
| 基础字段数 | `4` 个 |
| 嵌套字段数 | `2` 个 |
| 原始命中快照数 | `9` |
| 过滤后有效快照数 | `7` |

按各部件执行后的处理过程如下：

1. **查询构建部件**固定加入 `projectId=P001` 约束，并生成关键词检索请求。
2. **嵌套检索部件**在标题、子标题、描述、代码字段之外，同时对 `sqls.content` 与 `remotes.invokerInterface` 发起嵌套检索，使"超时"既可以命中描述，也可以命中 SQL 或远程接口。
3. **高亮抽取部件**把命中片段统一回填为结构化字段，例如：
   - `titleFragment=<em>超时</em>场景`；
   - `describeFragments=[支付回调出现<em>超时</em>]`；
   - `remoteContentFragments=[com.demo.PayService#notify]`。
4. **结果过滤部件**把原始命中的 `9` 个快照中过滤掉 `2` 个不可用快照，仅保留 `7` 个有效结果。
5. **结果映射部件**把每个有效结果统一映射为快照对象，输出 `snapshotId`、`directoryId`、`titleFragment`、`sqlContentFragments`、`remoteContentFragments` 和 `updateTime`。
6. **关系输出部件**在本例中不进入表级关系输出路径；若用户切换为 `TABLE` 模式并输入 `order_db.t_order`，则该部件会进一步生成"快照-数据表-动作标签"关系对象。

输出结果示例如下：

| 快照 | 命中域 | 高亮证据 | 更新时间 |
|---|---|---|---|
| `snapshot-123` | 标题、描述 | `<em>超时</em>场景`；`支付回调出现<em>超时</em>` | `2026-03-20 10:15:00` |
| `snapshot-126` | SQL | `select * from t_order where status='PAY_TIMEOUT'` | `2026-03-20 10:30:00` |
| `snapshot-128` | 远程接口 | `com.demo.PayService#notify` | `2026-03-20 11:00:00` |

本实施例中，系统先把检索范围锁定在项目 `P001` 内，再让基础字段和嵌套字段共同参与召回，并把多域高亮证据统一回填到一个结果对象中。这样用户只输入一次"超时"，就能同时看到标题、描述、SQL 和远程接口中的命中证据，显著缩短了故障定位路径。
